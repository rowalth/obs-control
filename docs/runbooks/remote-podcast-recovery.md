# Remote Podcast Recovery

Recovery keeps the guest in the current familiar path whenever possible.
Do not move a guest to an experimental platform during an incident.

## Riverside blocked before recording

1. Stop troubleshooting the guest's corporate firewall.
2. Open the prepared Teams meeting.
3. Send the Teams link through the existing conversation.
4. Run the Teams capture checks before recording.
5. Mark the mode change in the session manifest.

## Guest disconnect

1. Keep the host and safety recording running.
2. Ask the guest to reopen the same link.
3. Record the disconnect and reconnect times.
4. Make a new spoken sync marker after reconnection.

## OBS interruption

1. Keep the guest platform running.
2. Confirm whether the crash-resistant OBS file remains playable.
3. Restart only the approved podcast profile and collection.
4. Resume the safety recording after explicit approval.
5. Treat the platform's isolated tracks as master when Riverside was active.

## Missing upload or track

1. Keep the affected browser or app open while it continues uploading.
2. Preserve every available safety source.
3. Record the missing or partial file in the manifest.
4. Tell the editor which source replaces it.

## Low storage

Do not begin a real recording after the preflight reports insufficient storage.
Move to an approved recording volume, free space without deleting unverified source material, or reschedule.
